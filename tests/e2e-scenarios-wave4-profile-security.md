## 4. Password Change (API-level)

### Background

The password change feature has a `changePasswordSchema` validator in `lib/validators/user.ts` but no dedicated API route or UI yet. These API-level tests validate the schema contract so it's ready when the route is built.

### API: Change Password Contract

| Prio | Cat | Test Name | Description |
|------|-----|-----------|-------------|
| P0 | Success | PasswordChange_Valid_Data | POST /api/user/change-password with `{ currentPassword: "OldPass123!", newPassword: "NewPass456!" }` → 200 (schema validates) |
| P0 | Error | PasswordChange_Same_Password | Schema rejects when `currentPassword === newPassword` → validation error "Le nouveau mot de passe doit être différent de l'actuel" |
| P0 | Error | PasswordChange_Empty_Current | Schema rejects when `currentPassword` is empty → validation error "Mot de passe actuel requis" |
| P1 | Error | PasswordChange_New_Too_Short | Schema rejects when `newPassword` < 8 chars → validation error "Le mot de passe doit contenir au moins 8 caractères" |
| P1 | Error | PasswordChange_New_No_Uppercase | Schema rejects when `newPassword` has no uppercase letter → validation error |
| P1 | Error | PasswordChange_New_No_Number | Schema rejects when `newPassword` has no number → validation error |
| P1 | Error | PasswordChange_New_No_Special_Char | Schema rejects when `newPassword` has no special character → validation error |
| P1 | Error | PasswordChange_New_Too_Long | Schema rejects when `newPassword` > 100 chars → validation error |
