## Code Defects Discovered During Wave 4 Analysis

1. **No password change API route:** `POST /api/user/change-password` does not exist — password change tests return 404 instead of 200/400. The UI has the form but no backend handler.

2. **Delete account API requires password but UI doesn't send it:** `DELETE /api/user/profile` requires password in request body, but the UI confirmation dialog doesn't collect it — will always fail with `PASSWORD_REQUIRED`.

3. **No public API key CRUD for free-tier users:** `POST /api/user/api-keys` returns 403 for FREE plan, but the UI doesn't show the plan warning until after the modal opens. Confusing UX.

4. **No `/api/admin/promote` endpoint:** Admin-success tests blocked — no way to promote a user to ADMIN role for E2E coverage of admin features.

## Code Defects Discovered During Wave 3 Analysis

1. **Missing `[id]` route for email templates PATCH/DELETE:** `app/api/email-templates/route.ts` defines `PATCH` and `DELETE` accessing `params.id`, but `/api/email-templates/{id}` has no dynamic segment route. PATCH/DELETE will never receive `params.id`. Fix: create `app/api/email-templates/[id]/route.ts`.

2. **Missing `DELETE /api/user/integrations/gmail` route:** The integrations UI calls `DELETE /api/user/integrations/gmail` on disconnect, but no route file serves this path. The disconnect click will result in a 404.

3. **UI invite button uses `alert()` placeholder:** Teams settings page has `alert("Fonctionnalité d'invitation à venir")` instead of an actual invite flow.

4. **Join token page shows static placeholder for email:** `app/teams/join/[token]/page.tsx` shows `"(Email du compte)"` as a hardcoded string instead of the actual user email.

5. **No `/api/admin` route guard file:** Admin endpoints rely on individual `requireAdmin()` calls but there is no centralized middleware or layout guard for `/admin/*` routes.
