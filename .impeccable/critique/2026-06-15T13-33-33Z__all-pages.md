## Anti-Patterns Verdict

**LLM Assessment**: The site is clearly not a raw AI template — it has genuine engineering thought, real content, and working auth. But it *occasionally* looks like an AI-tuned project due to: the side-tab callout border on blog articles, gradient background on the blog CTA section, fake company names in social proof, and several accent typos that suggest non-native French copy. The overall feel is "competent B2B SaaS" with telltale rough edges.

**Deterministic Scan**: Detector found 2 warnings across 31 scannable pages:

1. **side-tab**: `border-l-4` at `blog/[slug]/page.tsx:115` — side-stripe accent border on the takeaway callout
2. **em-dash-overuse**: 6 em-dashes in `api/user/profile/route.ts` — AI cadence tell in API response text

## Overall Impression

ScreenCold has a solid, functional foundation. The dashboard is genuinely good — keyboard shortcuts, command palette, real-time metrics — and the marketing pages are clean. The product works and looks professional. The issues are in the margins: inconsistent year stamps, accent typos in French copy, one banned pattern (side-tab), and a few places where the visual language drifts (gradient, green icons, hand-coded textarea). A polish pass across the marketing pages would bring the site from "Acceptable" to "Good."

## What's Working

1. **Dashboard UX**: Command palette (Cmd+K), keyboard shortcut customization with live recording, leader key navigation — genuinely power-user friendly. Rare in a SaaS product at this stage.

2. **Consistent component vocabulary**: Cards, Buttons, Badges, and Inputs from `@screencold/ui` are used consistently throughout the dashboard. The design system is real and followed.

3. **Auth and Settings flows**: Login/register have clean validation, toast feedback, error recovery. Settings has a well-designed danger zone with clear irreversible-action warnings.

## Priority Issues

### P1 — Accent typos in French copy (4 pages)
**What**: Pricing page: "personnalises", "fonctionnalites", "Questions frequentes", "Pret a", "decouvrez", "genere", "Utilise par". About page: "precisas". FAQ page: "integrer". These are all missing required French accents.
**Why it matters**: For a French-native B2B sales tool, accent errors erode credibility immediately. Prospects evaluating the tool will question the quality of the product if the copy has typos.
**Fix**: Audit all French copy across marketing pages and fix missing accents.
**Suggested command**: `/impeccable clarify all-pages`

### P1 — Side-tab border on blog takeaway (blog/[slug]/page.tsx:115)
**What**: `border-l-4 border-info-600` on the takeaway callout box. This is an absolute ban in DESIGN.md.
**Why it matters**: It's the #1 AI-generated-UI tell. Users won't consciously notice but the interface feels subtly "off."
**Fix**: Replace with a full background tint (`bg-info-50`), no side border. The rounded-r-lg can become a plain rounded-lg.
**Suggested command**: `/impeccable polish blog/[slug]/page.tsx`

### P2 — Inconsistent year stamps (2024 vs 2026)
**What**: Landing page, pricing, about, contact, FAQ all say `© 2024`. Blog list says `© 2026`.
**Why it matters**: Inconsistency signals neglect. A 2026 site still showing 2024 looks abandoned.
**Fix**: Update all footers to `© 2026`.
**Suggested command**: `/impeccable polish`

### P2 — Gradient background on blog CTA (blog/[slug]/page.tsx:133)
**What**: `bg-gradient-to-r from-info-600 to-info-700` on the CTA section.
**Why it matters**: While not a text-gradient, the flat-by-default principle means gradients should be rare and purposeful. A solid `bg-info-600` would be more consistent.
**Fix**: Replace with solid `bg-info-600`.
**Suggested command**: `/impeccable quieter blog/[slug]/page.tsx`

### P2 — Fake company names in social proof
**What**: "WebBoost", "DigitalPro", "StudioUX", "AgenceSEO", "PixelCraft" — clearly generated placeholder names.
**Why it matters**: If a prospect recognizes these as fake, trust collapses. Real logos or verifiable testimonials would be far stronger. Without them, the social proof section actively harms conversion.
**Fix**: Either remove the section, use real client names (with permission), or replace with generic benefit statements.
**Suggested command**: `/impeccable clarify`

### P2 — Dark mode classes present but likely non-functional
**What**: Pricing page has `dark:bg-neutral-900`, `dark:text-white`, etc. throughout. Other marketing pages don't have dark mode at all.
**Why it matters**: Half-implemented dark mode creates an inconsistent experience if the user's system preference triggers it.
**Fix**: Either fully implement dark mode across all pages, or remove the dark: classes from pages that don't support it.
**Suggested command**: `/impeccable polish`

### P2 — Hand-coded textarea on contact page
**What**: Contact form textarea (line 140-146) uses direct `<textarea>` with inline classes rather than the `Input` component from `@screencold/ui`. Focus styling differs slightly from the standard Input.
**Why it matters**: Inconsistent form controls catch the eye of detail-oriented users. The textarea has `border-neutral-300` vs the standard `border-neutral-200`, and uses `focus:ring-1` vs the Input's `focus:ring-2`.
**Fix**: Use the shared Input component or create a Textarea component that matches.
**Suggested command**: `/impeccable polish contact/page.tsx`

### P2 — English text in admin observability page
**What**: "Healthy", "Unreachable", "Unable to parse metrics response", "Failed to fetch metrics", "Aucune donnée de job disponible" (mixed French/English).
**Why it matters**: The entire site is in French except this admin page. Even for admin users, consistency matters.
**Fix**: Translate all user-facing strings to French.
**Suggested command**: `/impeccable clarify admin/observability/page.tsx`

### P3 — Google icon monochrome on login
**What**: Google login button uses `fill="currentColor"` on all 4 SVG paths, resulting in a monochrome icon instead of Google's brand colors.
**Why it matters**: Small detail, but the Google sign-in button is a trust signal. The monochrome icon looks slightly off.
**Fix**: Replace with fixed fill colors (blue #4285F4, red #EA4335, yellow #FBBC05, green #34A853).
**Suggested command**: `/impeccable polish login/page.tsx`

### P3 — Missing meaningful alt text on blog images
**What**: Blog featured image (`blog/page.tsx:86`) and article cover image (`blog/[slug]/page.tsx:79-80`) both use `alt=""`.
**Why it matters**: Accessibility concern. Screen readers get no information about these images.
**Fix**: Add descriptive alt text pulled from article metadata.
**Suggested command**: `/impeccable audit`

### P3 — Freelance page uses green for feature icons
**What**: `freelances/page.tsx:95` uses `bg-success-100 text-success-600` for benefit card icons, while every other marketing page uses `bg-info-100 text-info-600`.
**Why it matters**: Inconsistent accent usage. Green is reserved for success states per the One-Voice Rule.
**Fix**: Change to `bg-info-100 text-info-600`.
**Suggested command**: `/impeccable polish freelances/page.tsx`

### P3 — Em-dash overuse in API route
**What**: `api/user/profile/route.ts` has 6 em-dashes in body text — an AI cadence tell.
**Why it matters**: Only visible in raw API responses, but still code quality.
**Fix**: Replace em-dashes with commas, colons, or parentheses.
**Suggested command**: `/impeccable clarify api/user/profile/route.ts`

### P3 — Leader key indicator logic bug
**What**: `(dashboard)/layout.tsx:115`: `leaderKey === "g" ? "D" : ""` — only shows "D" key hint when leader key is "g", empty string for all others.
**Why it matters**: Minor visual bug; power users who trigger leader mode see an incomplete key hint.
**Fix**: Show all available leader key options, not just when leaderKey === "g".
**Suggested command**: `/impeccable polish layout.tsx`

## Questions to Consider

1. **Would removing the fake company names and replacing with real logos or benefit statements improve conversion more than keeping the current social proof?** The placeholder names feel like the weakest trust signal on the site.

2. **Is the gradient background on the blog CTA worth keeping for visual variety, or does it violate the flat-by-default principle enough to change?** Aesthetic choice, but consistent with the design system would be flat.

3. **Should dark mode be completed or removed from the pricing page?** Half-implemented dark mode creates a maintenance burden.
